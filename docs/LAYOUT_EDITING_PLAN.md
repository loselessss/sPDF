# sPDF 조판·레이아웃 편집 업데이트 계획

작성일: 2026-08-31

상태: 검토용 초안 — 기능 구현·배포 전

기준: 1.19.0의 편집 작업 공간 + 1.19.1의 편집 전용 UI 정리

## 1. 목표와 범위

Illustrator 없이 PPT로 작업할 때 번거로운 **글·그림·도형의 정확한 배치와 문자 조판**을 sPDF 편집 창에서 처리한다. 반복적인 위치·크기·간격 맞추기를 줄이고, 편집 가능한 작업 파일과 선명한 배포용 PDF를 남기는 것이 목표다.

이 초안에서 ‘조판’은 한 페이지 안의 개체 배치와 글자·문단 서식을 뜻한다. 실제 작업 예시는 아직 확인하지 않았으므로, 아래 우선순위는 제안이다. 인쇄용 여러 쪽 모아 찍기·책자 접지 순서 배치는 별도 후속 과제로 구분한다.

### 우선 해결할 작업

| 작업 중 불편 | 필요한 기능 | 우선순위 |
| --- | --- | --- |
| 작업 도중 용지 규격이나 배치 영역을 바꿔야 함 | 캔버스 크기 변경, 상하좌우 조판 여백, 적용 미리보기 | 첫 배포 |
| 여러 그림의 폭·높이·간격을 계속 맞춤 | 같은 크기, 가장자리 정렬, 일정 간격, 기준 개체 | 첫 배포 |
| 눈대중으로 움직여도 미세하게 어긋남 | mm 좌표·크기 입력, 눈금자·안내선·스냅 | 첫 배포 |
| 그림·설명·라벨을 함께 옮기기 번거로움 | 다중 선택, 그룹, 잠금, 겹침 순서 | 첫 배포 |
| 글꼴·행간·자간과 문단 형태가 제각각임 | 문자·문단 속성, 재사용 가능한 스타일 | 기본 서식은 첫 배포, 정밀 조판은 다음 단계 |
| 그림 교체 후 배치를 다시 해야 함 | 프레임 유지 교체, 비율 잠금, 자르기 | 첫 배포 |
| 저장·재편집 과정에서 결과가 달라짐 | 작업 파일 재개방, PDF 내보내기, 글꼴·넘침 확인 | 첫 배포의 필수 조건 |

첫 사용 예시는 ‘A4 한 장에 그림 6개를 같은 폭과 간격으로 놓고 제목·라벨·설명을 추가하는 작업’으로 잡는다. 논문 그림, 설명서, 포스터 일부 등에 적용할 수 있는 예시이며 사용자 문서 유형을 확정한 것은 아니다.

### 이번 범위에서 제외

- Illustrator의 전체 기능 복제, 임의 AI 파일의 원본 편집 구조 복원.
- 모든 PDF의 기존 글·그림·패스를 자동으로 완벽한 편집 개체로 변환.
- 베지어 점 편집, 패스 합치기·빼기, 복잡한 마스크·블렌드·필터.
- 긴 책 전체의 자동 조판, 수식 엔진, 세로쓰기, 전문 인쇄소용 PDF/X·별색·ICC 처리.
- PPTX 직접 편집·왕복 저장. 초기에는 PPT에서 내보낸 PDF나 이미지로 가져온다.
- GPU 전용 PDF 엔진 교체. 조판 기능의 선행 조건으로 삼지 않는다.
- 내장 모드 정책 변경, 자동 OCR 실행.

## 2. 현재 코드에서 출발할 지점

- `pdfeditor/editor_workspace.py`: 바둑판 페이지 구성과 같은 창의 상세 편집 전환이 있다.
- `pdfeditor/editing.py`, `pdfeditor/core.py`: 기존 글자 교체와 새 글자 삽입, 크기·색상 변경이 있다. 현재 `add_text_box()`는 좌표에 글자를 쓰는 방식으로, 크기 조절 가능한 문단 프레임 모델은 아니다.
- `pdfeditor/widgets.py`: 텍스트 선택·손 도구·편집 영역 표시가 있다. 조판용 개체 선택·변형·그룹 모델은 아직 없다.
- `pdfeditor/conversions.py`: 이미지의 PDF 페이지 변환은 있지만, 여러 그림을 한 페이지에 자유롭게 배치하는 작업 공간은 아니다.
- 현재 일반 PDF 편집의 실행 취소는 PDF 바이트 스냅샷을 보관한다. 기존 `PLAN.md`의 연산 재생 구상과 실제 구현이 다르므로, 드래그할 때마다 전체 PDF를 복제하는 방식으로 확장하지 않는다.
- 현재 저장은 임시 파일 생성 후 교체한다. 이 안전성은 조판 작업 파일과 출력 PDF에도 유지한다.

기존 PDF의 줄 단위 수정과 새 조판용 텍스트 프레임은 다른 기능이다. 새 기능을 추가해도 ‘기존 PDF의 모든 문단이 자동으로 다시 흐른다’고 안내하지 않는다.

## 3. 사용 흐름과 화면 구성

1. 읽기 창은 그대로 유지하고, 큰 **편집 모드** 버튼으로 편집 창에 들어간다.
2. 편집 창은 기존처럼 페이지 바둑판에서 시작한다. 조판 작업에는 **새 조판 문서**와 **빈 페이지 추가**를 제공한다.
3. 페이지를 두 번 누르면 상세 편집한다. 여기서 **개체 선택 / 글자 편집 / 손 도구**를 명확히 구분한다.
4. 그림·PDF 일부·텍스트·도형을 배치하고 정렬한다.
5. 작업 파일을 저장하거나 **PDF로 내보내기**를 실행한다. 페이지 구성으로 돌아가도 개체·그룹·미저장 변경을 유지한다.

화면 배치는 다음 안을 우선 검토한다.

- **리본:** 캔버스 크기·여백, 삽입, 정렬·간격, 그룹·겹침 순서. 자주 쓰는 배치 버튼에는 아이콘과 짧은 이름을 함께 표시한다.
- **왼쪽:** 기존 페이지 썸네일·책갈피 영역. 상세 편집의 썸네일은 페이지 이동용이며 순서 변경은 바둑판에서만 한다.
- **중앙:** 페이지와 선택 핸들, 눈금자·안내선. 안내선은 출력되지 않는다.
- **오른쪽 접이식 속성 패널:** 선택 종류에 따라 위치·크기·각도 또는 문자·문단 속성을 표시한다. 창이 좁으면 접을 수 있게 한다.
- **개체 목록:** 이름, 표시·숨김, 잠금, 겹침 순서를 관리한다. PDF 내부의 모든 패스를 자동 나열하지 않고 sPDF 조판 개체부터 표시한다.

`[편집 전용]` 표시를 유지한다. 편집 창에 프레젠테이션·전체화면 버튼을 다시 추가하지 않으며, 기존 UI보다 글자와 패널을 불필요하게 키우지 않는다.

## 4. 1차 기능: 정확한 배치

### 4.1 개체 생성과 선택

- 빈 페이지: A4·A3, 가로·세로, 사용자 지정 가로·세로 mm. 생성 후에도 캔버스 크기·여백을 변경할 수 있다(4.6·4.7절).
- 텍스트 상자, 이미지, PDF 페이지·영역, 사각형·타원·직선·화살표.
- 클릭·범위 드래그·Shift 추가 선택, 개체 목록에서 선택, 선택 해제.
- 개체 이동·복제·삭제, 그룹·해제, 잠금·해제, 앞으로·뒤로 보내기.
- 잠긴 배경을 끌지 않게 하고, 겹친 개체는 목록에서 정확하게 고른다.
- 새 개체의 붙여넣기·복제는 sPDF 내부에서 우선 지원한다. 외부 클립보드는 일반 텍스트·비트맵부터 지원하며 PPT 개체가 벡터로 그대로 붙는다고 보장하지 않는다.

### 4.2 정렬·간격·크기

- 좌·가운데·우 / 위·중간·아래 정렬.
- 기준 선택: 페이지, 여백 안쪽, 선택 범위, 지정한 기준 개체.
- 같은 폭·높이·크기, 가로·세로 동일 간격.
- ‘중심 간격 동일’과 ‘개체 가장자리 사이 빈 간격 동일’을 구분한다.
- 간격을 mm로 직접 입력한다. 그룹은 하나의 경계 상자로 계산하며 잠긴 개체는 이동하지 않는다.
- 개체 하나만 선택했을 때의 페이지 정렬 등, 선택 수에 따라 가능한 명령만 활성화한다.

### 4.3 정밀 이동·변형

- X/Y, W/H, 회전 각도와 기준점 입력. 내부 좌표는 정밀도를 유지하고 표시만 반올림한다.
- 비율 잠금, 크기 조절 핸들, 키보드 미세 이동. 이동 단위는 설정 가능하게 한다.
- 눈금자, 드래그 안내선, 여백, 페이지 중심선, 개체 가장자리·중심 스냅.
- 현재 스냅 대상과 간격을 표시하고 일시 해제 수단을 제공한다.
- 회전 페이지·잘린 페이지·고해상도 화면에서도 같은 문서 좌표를 사용한다.
- 개체 회전과 PDF 페이지 자체 회전은 서로 다른 명령으로 유지한다.

### 4.4 그림 배치

- 파일 드롭 → 배치 미리보기 → 원하는 위치에 넣기.
- 비율 유지, 프레임 안에 맞춤 / 프레임 채움, 비파괴 자르기.
- 그림 교체 시 프레임·정렬 위치·크기는 유지한다. 새 원본의 비율이 다르면 미리보기로 확인한다.
- PDF의 한 쪽 또는 사각 영역을 **배치된 PDF 개체**로 가져온다. 내부 글자·패스는 이 단계에서 각각 편집하지 않는다.
- PDF 호환 `.ai`는 기존처럼 PDF 표현만 사용하고 AI 원본에 저장하지 않는다.
- SVG는 호환성 샘플 검증 후 추가한다. 변환 실패를 조용히 저해상도 이미지로 대체하지 않는다.

### 4.5 첫 배포의 기본 문자 기능

- 설치된 글꼴 선택, 글자 크기·색상, 실제 글꼴이 제공하는 굵기·기울임.
- 프레임 내부 줄바꿈, 좌·가운데·우 정렬, 내부 여백.
- 프레임 넘침 표시. 글자를 몰래 줄이거나 잘라 저장하지 않고, 축소·상자 확장·내용 수정 중 사용자가 선택한다.
- 글꼴 누락·대체를 분명하게 알리고 원본 스타일 정보를 남긴다.

### 4.6 캔버스 크기 변경

조판에서 캔버스는 각 페이지의 실제 용지·작업판 크기를 뜻한다. 화면 확대 비율이나 이미지 DPI 변경과 구분한다.

- A4·A3 등의 규격, 가로·세로 전환, 사용자 지정 가로·세로 수치 입력. 기본 단위는 mm이며 pt 표시도 지원하는 안으로 잡는다.
- 새 문서 생성뿐 아니라 작업 도중 변경도 지원한다. 현재 페이지 / 바둑판에서 선택한 페이지 / 전체 페이지에 적용하고, 서로 다른 크기의 페이지를 한 문서에 둘 수 있다.
- **기본은 내용 크기 유지:** 캔버스만 바꾸며 그림·글자·선 두께를 자동 확대·축소하지 않는다. 기본 기준점은 왼쪽 위이며, 가운데·모서리 등을 고르는 9점 기준점으로 내용의 상대 위치를 결정한다.
- **내용도 비율 유지해 맞춤**은 별도 선택 사항으로 제공한다. 이 경우 글자·선·그룹까지 포함한 전체 배치의 균일 배율과 위치 변화를 미리 보여주며, 가로·세로를 서로 다르게 늘려 왜곡하지 않는다.
- 캔버스를 줄였을 때 바깥으로 나가는 개체를 강조한다. 임의 삭제·자동 축소는 하지 않으며, 취소·크기 재조정·바깥 개체를 유지한 적용 중 선택한다. 바깥 개체는 작업 파일에 남겨 다시 가져올 수 있게 한다.
- 적용 전 새 경계와 내용 위치를 겹쳐 보여주고, 여러 페이지 변경도 한 번의 실행 취소로 되돌린다. 잠금 개체도 페이지 전체 변환에는 함께 따라가되 잠금 상태는 유지한다.
- PDF 내보내기의 실제 페이지 치수도 변경한 값과 일치해야 한다. MediaBox·CropBox 불일치로 새로 늘린 부분이 계속 잘리지 않게 검증한다.
- 기존 PDF의 **페이지 여백 자르기**와 별도 명령으로 제공한다. 초기에는 조판 문서에 적용하며, 가져온 PDF를 배치 개체로 썼다면 그 소스 파일 자체는 바꾸지 않는다.

### 4.7 조판용 여백과 배치 영역

- 위·아래·왼쪽·오른쪽 여백을 mm로 각각 설정하고, 연결 버튼으로 네 값을 함께 바꿀 수 있게 한다.
- 현재 / 선택 / 전체 페이지 적용과 문서 기본값을 구분한다. 새 페이지는 기본값을 따르되 페이지별 예외를 저장한다.
- 여백 안쪽을 배치 가능 영역으로 표시하고, 그 경계·중앙에 정렬·스냅할 수 있게 한다. 표시·숨김과 스냅 켜기·끄기는 독립적이다.
- 여백은 **출력되지 않는 조판 기준선**이다. 변경해도 내용 이동·크기 조절·자르기·문단 재배치를 자동 실행하지 않는다. 여백 영역에 맞추기는 별도 명령으로 실행한다.
- 캔버스 크기를 바꿔도 여백 수치는 기본적으로 같은 mm를 유지한다. 여백 합이 페이지 폭·높이 이상이 되거나 음수이면 적용을 막고 수정할 값을 알린다.
- 캔버스 바깥으로 나간 개체와 여백 안쪽 영역을 벗어난 개체를 다르게 표시한다. 여백 침범은 허용 가능한 배치 경고이며 저장을 무조건 막지 않는다.
- 페이지 여백, 텍스트 상자 내부 여백, 프린터의 인쇄 가능 영역, 재단용 도련은 서로 다른 설정으로 다룬다. 프린터를 바꿨다고 조판 여백이나 개체 위치가 바뀌면 안 된다.
- 첫 배포는 네 방향 여백을 필수로 한다. 안쪽·바깥쪽 맞쪽 여백, 제본 여유, 단 수·단 사이 간격 안내선은 다음 단계의 확장 후보로 두며 자동 다단 텍스트 흐름과 구분한다.

## 5. 2차 기능: 문자·문단 조판

개체 배치와 저장이 안정화된 뒤, 문자 조판을 다음 기능 배포의 중심으로 삼는다.

- **문자:** 선택 구간별 서식, 자간, 행간, 위·아래 첨자, 기준선 이동.
- **문단:** 문단 앞·뒤 간격, 들여쓰기, 탭 위치, 양끝 정렬, 프레임 내 세로 정렬.
- **스타일:** 제목·소제목·본문·캡션·라벨 스타일을 저장하고 여러 상자에 적용한다. 직접 지정한 예외 서식은 구분한다.
- **한국어·영문 혼용:** IME 조합, 문장부호 줄바꿈, 숫자·기호·그리스 문자, 글꼴 대체를 샘플로 확인한다.
- **넘침 확인:** 출력 전 넘치는 텍스트와 누락 글꼴 목록에서 해당 상자로 이동한다.

한 글자 쌍의 커닝 조절, 글자 가로 비율, 연결 텍스트 프레임, 여러 단에 걸친 자동 흐름은 별도 난도가 높은 항목이다. 0단계에서 출력 일치 가능성을 확인해 세부 범위를 결정하며, 단순 CSS 설정만으로 모두 구현된다고 가정하지 않는다.

기존 PDF의 본문을 조판 프레임으로 바꾸는 것은 자동 기본 동작이 아니다. 후속의 **선택 영역을 새 텍스트로 재작성** 기능으로 검토하며 원본 비교·글꼴 대체 확인이 필요하다. 스캔본은 OCR을 해도 사진 속 개체가 분리되는 것은 아니다.

## 6. 3차 기능: 반복 작업과 출력 보강

- 행·열 개수와 간격을 입력하는 배열 복제, 여러 그림의 그리드 배치.
- A/B/C 또는 1/2/3 패널 라벨, 번호 시작값·순서·위치·스타일 지정. 자동 갱신 여부는 사용자가 선택한다.
- 제목·그림·캡션이 묶인 템플릿, 페이지 여백·안내선·스타일 재사용.
- 공통 요소의 여러 페이지 적용과 페이지별 예외 관리.
- 선택 개체·그룹·영역을 PDF 또는 PNG/JPEG로 내보내기.
- 출력 전 저해상도 이미지, 페이지 밖 개체, 누락 자산·글꼴, 텍스트 넘침 검사. DPI 기준은 출력 용도별로 선택한다.
- 기본 도형의 선 두께·색·채움·투명도 보강. 전문 벡터 드로잉 기능은 별도 판단한다.

여러 쪽 모아 찍기, 책자 순서 배치, 재단선·도련, 본격적인 색상 관리는 이후 별도 계획으로 분리한다. 단순 RGB PDF 내보내기를 인쇄소 납품 품질 보장으로 안내하지 않는다.

## 7. 저장·재편집 설계안

### 작업 파일과 결과물을 구분

- **일반 PDF 편집:** 현재의 Ctrl+S·다른 이름으로 저장을 유지한다. 기존 파일을 동의 없이 조판 프로젝트로 전환하지 않는다.
- **조판 문서:** 새 전용 작업 형식 `*.spdf-layout`을 제안한다. 확장자·형식은 구현 전 확정한다. Ctrl+S는 편집 가능한 작업 파일을 저장하고, 별도의 **PDF로 내보내기**가 배포 결과물을 만든다.
- 작업 파일은 버려도 되는 임시 중간파일이 아니라 **재편집용 원본**이다. PDF 출력 방식과 관계없이 원래 문자열·서식·개체 구조를 유지한다. 자동 복구용 임시파일과도 구분한다.
- 결과 PDF는 다른 PDF 뷰어에서 열 수 있어야 한다. 그러나 결과 PDF만 다시 열어서 그룹·스타일·편집 이력까지 복원하는 것은 첫 버전에서 보장하지 않는다.
- 기존 PDF를 조판 재료로 사용할 때는 원본을 유지한 파생 작업 문서를 만든다. 기존 PDF 수정 기능과 새 배치 작업의 저장 대상을 UI에서 구분한다.

### 작업 파일에 포함할 정보

- 형식 버전, 안정적인 페이지·개체 ID, 페이지별 캔버스 크기·방향·여백과 문서 기본값, 위치·변형·겹침 순서, 그룹·잠금, 안내선·스타일.
- 원래 유니코드 문자열, 문자 구간별 서식, 문단 설정, 텍스트 프레임 크기와 넘침 상태. 윤곽선 PDF를 내보낸 뒤 저장해도 이 정보를 경로 데이터로 대체하지 않는다.
- 원본 또는 명시적으로 선택한 기준 PDF 사본과 사용한 그림·PDF 자산. 기본은 자산 포함으로 제안해 파일 이동 후 경로 단절을 줄인다.
- 글꼴 이름·특성·대체 기록. 글꼴 파일의 포함 여부는 사용 허용 범위를 확인하고, 무조건 수집·재배포하지 않는다.
- 하나의 컨테이너 안에 모델과 자산을 묶되 원본 자산은 중복 저장을 줄인다. 컨테이너는 원자적으로 교체한다.

암호 PDF를 평문 프로젝트 자산으로 몰래 복사하지 않는다. 첫 버전은 보호된 소스의 프로젝트 포함을 제한하는 안을 우선 검토하고, 암호 저장 금지·명시적 안내를 적용한다. 외부 작업 파일을 열 때 경로 탈출, 과도한 압축 해제 크기, 악성 외부 참조를 제한한다.

### PDF 출력 시 글자 처리 선택

여기서 outline은 **글자 윤곽선(벡터 경로)**이다. 기존 TXT → PDF 책갈피(outline) 가져오기와 다른 기능이므로 UI에는 ‘outline’만 단독으로 쓰지 않는다.

| 저장·출력 종류 | 남기는 정보 | 용도 |
| --- | --- | --- |
| 작업 파일 저장 | 원래 글·서식·개체·그룹·캔버스·여백·자산 | 다음 작업에서 계속 수정할 원본 |
| PDF — 텍스트 유지 (기본) | 글자를 PDF 텍스트로 유지, 허용되는 글꼴 포함 | 일반 배포, 글자 선택·검색·복사 |
| PDF — 글자를 윤곽선으로 변환 | 글자 모양을 벡터 경로로 출력 | 글꼴 의존성을 줄인 고정 모양 결과물 |

- **텍스트 유지:** 글꼴 포함 가능 여부와 누락 글꼴을 사전 점검하고 임의 대체하지 않는다. 선택·검색·복사 결과도 확인한다. 텍스트가 남는다는 것이 원래 텍스트 프레임·문단·그룹이나 Illustrator 전용 편집 정보까지 보존한다는 뜻은 아니다.
- **윤곽선 출력:** 작업 문서가 아닌 출력용 사본에서만 변환한다. 그림으로 찍어내는 래스터화와 구분하고, 원래 글을 수정하려면 작업 파일을 다시 연다. 글자를 경로로 바꾸면 문자 속성을 잃어 텍스트 도구로 수정할 수 없다는 점은 [Adobe 공식 설명](https://helpx.adobe.com/illustrator/web/add-and-edit-artwork/create-text/create-outline-text.html)과 같다.
- 윤곽선으로 바뀐 글자는 일반 텍스트 선택·검색·복사 및 보조기기의 읽기에 제약이 생긴다는 경고를 출력 창에 표시한다. 검색 기능을 남기려고 숨은 원문/OCR 텍스트를 몰래 덧붙이지 않는다. 변환하지 않은 원본 PDF의 OCR 레이어를 일반 저장 경로에서 없애지도 않는다.
- 대상은 최종 PDF에 포함되는 글자 전체를 목표로 한다. 다만 **sPDF에서 작성한 글자**와 **가져온 PDF·PDF 호환 AI 내부 글자**의 변환 경로를 따로 검증한다. 내부 글자·숨은 텍스트·지원하지 않는 글꼴이 남는 경우 ‘전체 윤곽선 변환 완료’로 표시하지 않는다. 해당 출력은 중단하고 원인과 텍스트 유지 출력 대안을 안내한다. 부분 변환을 제공하게 되면 대상 범위를 명시한 별도 옵션으로 구분한다.
- 글꼴이 없거나 변환이 허용되지 않는 경우 윤곽선 변환이 해결책이라고 가정하지 않는다. 잘못된 대체 글꼴로 모양을 확정하거나 조용히 이미지로 바꾸지 않는다. 전체 윤곽선 출력이 안전한 문서 범위는 0단계 실험 후 확정한다.

### 저장 UI와 원본 보호

- 조판 문서의 **저장 / 다른 이름으로 저장**은 작업 파일을, **PDF로 내보내기**는 결과 PDF를 다룬다. 일반 PDF 문서의 기존 저장 방식은 바꾸지 않는다.
- 내보내기 창 안에 **글자 처리: 텍스트 유지 / 글자를 윤곽선으로 변환**을 둔다. 새 문서의 기본값은 텍스트 유지이며, 문서별 마지막 출력 설정을 기억하더라도 실행 전에 현재 선택과 경고를 보여준다.
- 기본 출력 이름은 `문서.pdf`와 `문서_outlined.pdf`처럼 구분한다. 작업 파일·입력 자산과 같은 경로로 출력하지 못하게 하고, 기존 결과 PDF 교체는 확인을 받는다.
- 미저장 작업은 먼저 작업 파일 저장을 권한다. 사용자가 출력만 선택하더라도 ‘작업 원본은 아직 저장되지 않음’을 유지하며, PDF 출력 성공을 프로젝트 저장 완료로 처리하지 않는다.
- 작업 파일과 PDF 모두 임시 새 파일에 쓴 뒤 검증에 성공했을 때만 대상 파일을 교체한다. 출력 실패·취소 시 기존 파일과 편집 상태를 유지한다.

## 8. 구현 구조와 주요 기술 검증

새 코드는 `app.py`에 몰아넣지 않고 기존 창 조립·문서 처리 구조에 연결한다. 아래 모듈명은 제안이며 아직 생성하지 않는다.

- `layout_model`: Qt와 독립적인 페이지·개체·그룹·스타일 데이터.
- `layout_commands`: 추가·이동·크기·정렬·삭제·그룹·캔버스 치수·여백의 재생 가능한 연산. 드래그 전체를 실행 취소 한 번으로 묶고, Esc 취소 시 연산을 남기지 않는다.
- `layout_canvas` / `layout_inspector`: 선택·핸들·스냅과 속성 패널. 텍스트 선택과 개체 선택을 분리한다.
- `layout_store` / `layout_export`: 작업 파일 저장과 PDF 출력을 분리한다. 출력 실패가 편집 상태를 지우거나 원본을 교체하지 않아야 한다.

### 먼저 검증할 네 가지

1. **좌표:** 페이지 회전·CropBox·배율·화면 배율을 통합 변환하고 UI와 출력에 같은 수치를 쓴다.
2. **문자:** 글꼴 측정·줄바꿈·자간 결과가 화면과 PDF에서 맞아야 한다. 한 렌더링 결과를 미리보기와 출력에 공통 사용하고, 입력 중 임시 미리보기와 확정 결과의 차이를 검증한다. 텍스트 유지·윤곽선 출력 모두 한글·합자·기호·회전·변형·채움·선의 모양과 위치를 비교한다. 기존 PDF 내부 글자의 윤곽선 변환은 별도 검증하며, 현재 API 후보만으로 구현이 확정됐다고 보지 않는다.
3. **실행 취소:** 현재 PDF 스냅샷 체계와 조판 연산 기록을 문서 종류에 맞게 연결한다. 같은 작업 공간에서 서로 모르는 두 Ctrl+Z 스택을 만들지 않는다. 페이지 순서 변경 시 개체는 페이지 ID를 따라가야 한다.
4. **저장 왕복:** 저장 후 다시 열어 모든 개체의 좌표·그룹·스타일·그림 자르기가 유지돼야 한다. 복구 사본과 미저장 탭 이동도 조판 모델·자산을 함께 다룬다.

### PDF·텍스트 처리 후보의 근거

현재 개발 환경의 PyMuPDF는 1.28.2이며 `show_pdf_page()`와 `insert_htmlbox()` API가 존재한다. 존재 여부만 확인했으며 조판 품질 검증이 끝났다는 뜻은 아니다.

- `show_pdf_page()`는 다른 PDF 페이지를 이미지화하지 않고 배치할 수 있어 PDF 그림 배치 후보로 삼는다. 단, 주석·폼·링크를 자동 복사하지 않고 잘라 보이지 않는 자원도 남을 수 있다. 따라서 자르기를 개인정보 제거 기능으로 안내하지 않으며, 필요한 주석 보존·지원 불가 안내를 검증 항목으로 둔다. 일반 PDF 저장 경로를 이 API만으로 대체하지 않는다. [공식 문서](https://pymupdf.readthedocs.io/en/latest/page.html#Page.show_pdf_page)
- `insert_htmlbox()` / Story는 서식 있는 텍스트 배치 후보로 검토한다. 자동 축소를 허용하지 않는 설정과 넘침 결과를 활용하되, 필요한 한글 조판·정밀 자간을 충족하는지는 별도 실험한다. [공식 문서](https://pymupdf.readthedocs.io/en/latest/page.html#Page.insert_htmlbox)

### 성능 원칙

- 드래그 중 PDF 전체를 다시 저장·렌더링하지 않고 선택 개체의 미리보기 변형을 우선 표시한다. 확정 후 영향을 받는 부분을 갱신한다.
- 활성 페이지와 주변 미리보기만 유지한다. 큰 이미지의 원본·썸네일·화면용 사본이 무제한 중복되지 않게 캐시 상한을 둔다.
- 기능을 쓰지 않는 읽기 창에 조판 편집 의존성이나 글꼴 전체 분석을 미리 올리지 않는다.
- 많은 개체가 있는 페이지에서 드래그 지연·메모리·탭 닫기 시간을 측정한다. 숫자 목표와 지원 규모는 0단계 기준 장비·샘플을 정한 뒤 기록한다.
- 기존 CPU 렌더와 GPU 이미지 합성을 혼동하지 않는다. GPU 엔진 연구는 이 계획과 독립적으로 유지한다.

## 9. 개발 순서와 완료 기준

| 단계 | 결과물 | 다음 단계로 넘어가는 기준 | 상대 부담 |
| --- | --- | --- | --- |
| 0. 기반 검증 | 개체 모델·저장 왕복·좌표·텍스트 유지/윤곽선 출력의 작은 실험 | 원본 보존, 재편집, 화면·출력 일치 및 윤곽선 변환 가능 범위가 확인됨 | 중간, 문자 엔진은 불확실성 큼 |
| 1. 배치 첫 배포 | 4절의 캔버스·여백·기본 개체·정렬·속성·기본 문자·작업 파일·PDF 출력 | 아래 대표 작업을 처음부터 재개방까지 완료 | 중간~큼 |
| 2. 문자 조판 | 5절의 문자·문단·스타일·넘침 확인 | 한글·영문 혼용 샘플의 줄바꿈·서식이 출력과 일치 | 큼 |
| 3. 반복·출력 | 배열·라벨·템플릿·영역 출력·사전 점검 | 그림 교체·반복 페이지 작업에서도 배치와 스타일 유지 | 중간 |

날짜와 버전 번호는 아직 예약하지 않는다. 각 단계의 검증을 통과한 실제 기능 배포는 minor, 기존 동작 수정은 patch로 올린다. **계획서 작성만으로 현재 1.19.1을 올리거나 릴리스 노트에 미구현 기능을 추가하지 않는다.**

### 대표 작업의 완료 기준

- [ ] A4에서 사용자 지정 크기와 가로 방향으로 바꿔도 기본 모드에서는 글자·그림 크기가 유지되고 선택한 기준점에 맞게 배치된다.
- [ ] 내용 함께 맞춤은 명시적으로 선택했을 때만 적용되며, 미리보기와 PDF 출력의 배율·위치가 일치한다.
- [ ] 캔버스 축소 시 바깥 개체를 경고하고 작업 파일에는 보존한다. 실행 취소로 크기·배치·여백을 복구할 수 있다.
- [ ] 상하좌우 여백을 다르게 설정하고 여백 기준 정렬·스냅을 사용한다. 여백 변경만으로 개체가 움직이지 않고 안내선이 출력되지 않는다.
- [ ] 크기가 다른 여러 페이지에 여백을 일괄 적용할 때 잘못된 값은 적용 전에 알리고, 설정 저장·재개방 후 페이지별 값이 유지된다.
- [ ] 빈 A4 페이지에 그림 6개를 놓고 폭 55 mm, 가장자리 간격 4 mm로 3열 배치한다.
- [ ] 제목과 A–F 라벨, 설명을 추가하고 각 그림과 그룹으로 묶어 함께 이동한다. 첫 배포의 라벨은 일반 텍스트로 작성해도 된다.
- [ ] 그림 하나를 교체해도 프레임 크기·위치가 유지된다.
- [ ] 마우스 드래그·수치 입력·정렬 결과가 같은 좌표로 저장되며 반복 변형 후 값이 누적해서 틀어지지 않는다.
- [ ] 움직임 하나를 실행 취소·다시 실행하고, 페이지 순서 변경 후에도 개체가 올바른 페이지를 따라간다.
- [ ] 작업 파일을 닫고 다시 열어 그룹·서식·자르기를 계속 편집한다.
- [ ] 텍스트 유지 PDF를 다른 뷰어에서 열어 글자·그림·선의 위치와 모양, 한글·영문 선택·검색·복사를 확인한다.
- [ ] 윤곽선 PDF의 글자 모양·위치를 텍스트 유지 출력과 비교하고, 실제 벡터 경로인지 확인한다. 변환 대상 글자가 일반 텍스트 추출에 남거나 숨은 텍스트로 복제되지 않았는지도 확인한다.
- [ ] 두 출력 방식 모두 작업 파일의 원문·서식·그룹을 바꾸지 않는다. 출력 후 작업 파일을 저장하고 다시 열어 문구를 수정할 수 있다.
- [ ] 가져온 PDF 내부 글자 등 변환 불가능한 대상이 있으면 전체 윤곽선 출력 완료로 처리하지 않고, 기존 결과물을 보존한 채 원인을 안내한다.
- [ ] PDF 출력만으로 미저장 표시가 사라지지 않으며, 취소·실패·기존 출력 교체에서도 작업 원본과 입력 자산이 보존된다.
- [ ] 글꼴 누락·넘침·읽기 전용 폴더·저장 실패·보호된 소스를 조용히 무시하지 않는다.
- [ ] 많은 개체와 고해상도 이미지, 회전·잘린 페이지에서 응답성·메모리를 측정하고 숨긴 탭의 불필요한 작업이 멈추는지 확인한다.
- [ ] 읽기 모드·기존 PDF 편집·수동 OCR·내장 모드가 퇴행하지 않는다.

## 10. 구현 전 확인할 사용자 선택

초안을 막는 질문이 아니라, 실제 개발을 시작할 때 범위를 좁히기 위한 확인 사항이다.

1. 가장 힘든 실제 작업 한 가지: 그림 여러 개 정렬인지, 문단·자간·행간인지, 인쇄용 모아 찍기인지.
2. 대표 결과물 한 장 또는 익명화한 예시: 종이 크기, 가져오는 원본 형식, 자주 쓰는 글꼴, 원하는 출력 방식.
3. 작업 파일의 최종 확장자와 자산 포함 정책. 저장·출력은 7절의 ‘재편집 원본 + 텍스트 유지/윤곽선 PDF’로 구분하는 안을 기준으로 한다.

현재 추천 시작점은 **정확한 개체 배치 + 기본 문자 서식 + 재편집 가능한 저장**이다. 실제 불편의 중심이 문자 조판이면 0단계에서 문자 엔진을 먼저 검증하고 1·2단계의 배포 범위를 조정한다.
